# 00 · 构建前预检与 Commander 分工

> 执行前检查实际能力；此文件是自主决策清单，不是要求用户逐项答题。

## 范围与路径

1. 明确现有 Vault 根目录、课程目录和授权输入文件；不从示例路径推断真实文件存在。
2. 列出课程内被指定或明确属于本次任务的 PDF、PPT、PPTX、讲义等资料；防止把同目录的无关文件当作输入。
3. 判断原始章节/讲次先后，记录不确定的顺序；分散课件共同构成一门课，不强行改造成一本虚构教材。
4. 检查 `README.md`、`QA.md`、`raw-markdown/`、`notes/`、`assets/`、`review/` 是否已存在；优先恢复，避免覆盖既有有效资料。若 README 已有用户内容，不直接替换整个文件。
5. 检查文件读写权限、当前上下文/额度、静态检查脚本/绘图环境；确认实际能力，不承诺后台继续。

## OCR 工具与能力

动态查询当前运行环境中可用的小米 OCR MCP 接口，核对参数、文件输入类型、输出形式、页码与图像能力，先小样本试调用。不能仅因用户拥有 MCP 就认定当前 Agent 会话可调用它。支持类型不足时，只有在**当前环境有可靠的转换能力**且不损坏原件时才进行预转换，记录转换来源；否则记录失败并处理其他文件。详见 `references/01-ocr.md`。

## 执行身份与资源选择

- **Single-Agent**：没有实际子 Agent 调用权限、任务规模不大，或移交成本明显更高。自己完成所有阶段；直接维护 README 与 QA。
- **Commander-Orchestrated**：确认真实存在可调用 Worker 的接口、权限、可读文件、能力及当前可用额度后再决定并行。Commander 自主采用**混合分工**：优先按完整课件/章节安排 Worker；需要时批量 OCR、数学难点和高风险 QA 专项分配。不是 Agent 越多越好。
- **Worker-Agent**：优先服从明确的任务契约，只读取必要上下文，只写授权范围。若遇依赖、文件冲突、OCR 故障，记录并上报协调者，不擅自修改全局 README 或其他 Worker 产物。

### Commander 选择拆分的判断因素

课程大小、章节可独立性、前置知识依赖、Agent 在学科/工具上的实际表现、响应延迟、额度与 token 成本、交接次数、文件并发冲突风险、质量复查成本。对高度依赖的内容可串行或让一个 Worker 连续负责。

### 每项任务必须明确的契约

| 项目 | 必需说明 |
|---|---|
| Task ID / 负责人 | 唯一标识、实际 Worker 或协调者 |
| 输入 | 源文件与对应原始 Markdown（若已具备） |
| 范围与依赖 | 章节/小节及允许读取的前置资料 |
| 允许写入 | 精确到工作输出目录或文件，避免交叉覆盖 |
| 质量标准 | 2A 排版、教学规范、L1/L2/必要的 L3 检查 |
| 交付 | 输出文件清单、图像、QA 摘要、关键词/双链建议、失败项 |
| 异常处理 | 记录来源页及错误，不猜测；局部隔离后继续独立任务 |

单一 README 写入者通常由 Commander 担任或明确指定。Worker 不并发编辑共享 `README.md` / `QA.md`，在多 Agent 任务中可将交接记录写入 `handoffs/<task-id>.md`（仅在需要时创建）。协调者逐一验收并合并。所有笔记和复习索引按逻辑课程顺序组织，不依赖 Worker 完成先后。

## 预检结果与启动条件

以几句话记录：Vault/课程路径、输入范围、执行模式、实际 OCR 工具能力、风险与工作分配。能安全执行就直接开始；若无法读取必要源材料、缺失关键权限，报告受阻范围。无子 Agent 环境不得伪称已经分发任务；可以给出可复制任务契约，但当前任务仍按能力推进。
